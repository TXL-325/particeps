# 母机 Agent 基础管理与 IPv4 端口

本规格负责实例管理、凭据、端口与 Web/API 的用户可见行为。需求来源和验收见[brief](../../brief.md)，阶段与结果由 Runtime 管理；后续首期功能仍保留在[完整首期管理目标](../../../../../planning/first-release/specs/agent-management/spec.md)。

## 认证与凭据

当前 Web 与 /api/v1 的创建、查询、端口修改、单台启停和删除共用业务服务。未认证请求拒绝；只读 Token 只能查询，管理 Token 可执行当前管理操作，撤销立即失效。管理员会话写入执行来源校验，调用者不能通过接口差异绕过权限。对应本次 A2。

管理员密码保存不可逆哈希，API Token 保存校验摘要。自动生成的每实例初始密码加密暂存，通过管理权限的一次领取提供；普通列表/任务查询和日志不回显。领取后清除，15 分钟交付期过期后不可领取并清除暂存内容；页面清除、任务/实例切换和迟到响应不能重新显示已清除凭据。错误路径不得记录明文。对应本次 A3。

初始管理员由安装流程交付，默认监听与 Cookie 配置见[项目规格的部署与发布](../project-foundation/spec.md#部署与发布)。管理员交付与实例的一次性领取是不同流程，二者均不允许普通查询或日志返回密码。对应本次 A13。

这些是当前创建流程的必需保护。完整 SSH、公钥/密码策略、重装、密码重置与终端权限仍按原 A38–A41/A53/A54/A60 在后续交付收口，不把当前部分保护当作原条目整体通过。

## 创建与结果

初始选项包含 Alpine、Debian 13，默认 Alpine。默认模板沿用 Alpine 0.5 核/128 MiB/1 GiB、Debian 13 0.5 核/256 MiB/4 GiB；展示配置额度时不宣称已完成压力验收。资源参数保留必要有效性校验，不去掉 cgroup 限制绕过启动失败。

正常批量创建至少两台可分别识别的 Incus 系统容器。任务与实例结果可查询，创建步骤明确区分受理、容器创建、网络配置和就绪结果；对两种系统分别核对实际运行系统、镜像来源、管理 ID 与 Incus 对象。不能凭任务 ID 或 running 状态忽略实际错误。对应本次 A4。

当前只对经核对的实验 IPv4 网桥及入口实施本次端口交付。严格 IPv4-only、完整地址池能力、指定出口 SNAT、独立地址和 IPv6 创建由后续交付完成；界面和文档明确其状态。

## 端口分配与编辑

默认池 20000–59999，初始每台 20 个连续号码，池和数量可调整。同一号码的 TCP/UDP 归同一实例，按号码计数而非规则条数。首个 TCP 默认转到 22，其余 TCP 和全部 UDP 同号，不额外占用 SSH 号码。对应本次 A5。

已有实例可自动追加、指定可用号码或按协议编辑目标。操作后号码归属不变，实际转发与新查询/界面一致。SSH 标记只反映实际目标，映射到 22 不代表 SSH 服务或凭据已验证。对应本次 A7。

## 共享 IPv4 入口与归属

至少两台受管实例可共用一个明确属于实验母机的 IPv4 入口。每条规则保持实例归属，修改一台只替换其规则，不改变另一台的规则和既有连接。外部客户端分别验证 TCP 与 UDP 的实际目标。对应本次 A6、A7。

分配在统一账本中预留并检查已有 Incus forward 与宿主 TCP/UDP 占用，自动跳过冲突、手工冲突拒绝，并发不分得重叠号码。不能接管外部 forward 或清理混入外部规则的对象。固定 Incus 6.0.4 的 If-Match 未提供已验证的 CAS；当前边界采用单数据库写者、归属检查与写前记录，不承诺外部工具并发修改所属对象。

## 电源与映射

本次核验单台停止和启动：保留号段、追加号码和自定义目标；停止时暂停该实例 DNAT，其他实例保持可达。启动后观察实际内部 IPv4 再重绑；地址暂缺则显示等待并保留归属，不能把旧 DHCP 地址继续当作归属证明。恢复后的原 UDP 客户端不需要更换源端口。对应本次 A8。

写入或电源操作结果未确认时，不自动重放不确定动作或释放号码；保留可查询状态和原因。完整批量生命周期、重启/重装保留、期望状态协调和自动任务恢复属于原 S2 范围；重装尚未实现时明确拒绝，不能先停机再返回假成功。

## 删除、连接清理与结果不明

删除先记录清理状态，摘除本实例规则并精确清除相关 NAT/非 NAT 连接，再停止/删除实例并确认其已不存在，最后事务释放号码。失败或结果不明时保留占用、待处理状态和错误，阻止危险重复操作及重新分配。对应本次 A9。

目标编辑和恢复映射按旧连接的目标关联清理，不能把新目标或另一实例的连接误删。删除一台后另一台规则和 TCP/持续 UDP 保持正常；回收号码给新实例不能让旧入口流量误投。成功路径使用真实实验，故障注入与真实故障分别标明。

## Web、API 与状态

Web 提供本次创建、实例/端口查询、追加/指定、目标编辑、停止/启动和删除；API 提供相同业务规则与对应契约/示例，管理界面不能仅显示字段而没有可执行路径。实际浏览器操作与 API 结果分别验证。对应本次 A10、A12。

修改后必须取得新查询结果才能恢复“已应用”或 SSH 标记；刷新失败显示未确认，保留最后数据时明确其状态。切换实例、离开页面或清除凭据后，旧请求不得覆盖当前对象。等待地址、清理未完和结果不明可区分，不能提供会盲目重放不确定动作的按钮。

现有基础指标可保留，但不因本次交付而宣称完整图表、实时进程 CPU、分钟汇总、周期流量或规模监控完成。其原完整要求继续保留。

## 完成边界

本次 A1–A13 必须按当前候选验收，A13 优先。原 A32 的重装、原 A34 的指定出口、原 A43–A46 的全生命周期恢复、原 A53/A54 的未来访问路径，以及完整 Web/API 要求均不通过缩范围自动完成。完整首期最终仍复核全部原 81 项。
