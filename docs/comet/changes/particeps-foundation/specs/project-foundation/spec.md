# particeps 基础交付

本规格负责交付物、部署运维的用户可见行为和资源边界。需求来源、决定与验收见[brief](../../brief.md)；管理操作由[管理规格](../agent-management/spec.md)定义，工程机制由[架构规格](../agent-architecture/spec.md)定义。阶段、确认边界与验收结果由 Runtime 管理。

## 交付物与归属

particeps 在独立工作区维护源码、需求与证据；runman-agent 是参考项目，不因本 change 被修改。交付 Linux amd64 Go Agent，内嵌 Vue Web 并提供 /api/v1，在已准备的 Debian 13 Incus 实验母机运行。对应本次 A1。

Agent 常规操作只管理本系统登记并能核对归属的 Incus 系统容器。管理 ID、Incus 对象、端口记录和查询对象一致；其他工具或预先存在的实例不自动接管、修改或删除。当前操作均受认证、权限与来源校验约束。脚本的显式全卸及独立 Incus 清除按下文单独限定，不赋予 Web/API 接管外部实例的权限。对应本次 A1、A2、A13。

## 首期承诺与本次边界

本次完整交付包含 GitHub Release 安装运维脚本，以及基础实例管理和指定 IPv4 入口的端口闭环：初始系统创建、端口预留与按需启用、共享转发、端口追加/编辑、单台停止/启动、删除清理、当前凭据交付及对应 Web/API。Alpine 与 Debian 13 的实际系统、cloud-init 终态、适用 SSH 服务和请求的登录策略都需要核对。对应本次 A13、A3–A10。

端口默认值按 2026-09-13 用户修订执行：每台默认预留 20 个连续可映射号码、默认仅 TCP，只有首个 TCP 到实例 22 自动启用；创建时可选同段 UDP，选中的 UDP 默认不映射。前端展示可用号段，支持按协议启停映射与编辑目标，禁用保留号码归属。新默认值不关闭已存在实例的旧映射。详细分配及追加规则见管理规格；历史首期的冲突语义由 brief 的 N20/N21 和 D62/D63 替代，不重写历史基线。

## 部署与发布

本轮菜单保留安装或更新、查看状态、恢复备份、全部卸载、仅卸载 Agent 五项入口；主菜单 0 退出，无效输入重新选择。主菜单、参数输入、执行前确认、结果页和日志查看页属于静态页面：Ctrl+C 直接退出整个脚本，不显示“已取消当前输入”，不重新绘制菜单。结果页按回车返回发起操作的菜单。

“2. 查看状态”进入子菜单：1 启动 Incus、2 停止 Incus、3 启动 Agent、4 停止 Agent，R 刷新，L 查看日志，回车或 0 返回主菜单。每次启停获取安装锁，回读实际服务状态后报告结果；失败、未安装或状态未确认时显示原因并保留日志。结果页回车返回状态子菜单并刷新，失败可重新预检后重试。Incus 服务及存在的 socket 一并启停，防止停止后被 socket 唤起；不修改开机自启配置。启动 Agent 会按服务依赖启动 Incus。启停执行中 Ctrl+C 等待已提交的服务操作完成并核对，成功后回状态子菜单，失败仍展示结果页。命令行 --status 保持只读输出。对应本次 A13。

首次安装、更新、恢复备份、仅卸载 Agent 执行中可软中断：Ctrl+C 后停止安排后续正常步骤；正在写入文件、处理软件包或恢复数据时先让当前步骤安全结束，再回退；等待或回退期间重复按 Ctrl+C 不重复发起回退、也不强行结束恢复。回退成功后显示结果并返回主菜单；回退失败列出未恢复项目、原因和恢复材料位置，等待回车。不能在刚收到 Ctrl+C 时就显示“已取消”或“已恢复”，也不能把清理暂存文件当作回退完成。

首次安装回退同时清理本次新增的软件包，包括本次新装的 Incus 和依赖；安装前已有的软件包保留。以安装前清单和本次安装记录区分归属，不把系统原有闲置包顺带删除；不承诺把整个系统恢复到历史快照。回退所需工具在用完之前不能先卸掉。不得留下管理员已创建但密码未交付的无法登录状态。

全部卸载与随后单独确认的 Incus 清除：执行前确认页 Ctrl+C 仍直接退出；确认并开始后忽略 Ctrl+C，继续完成该次已确认的删除。不可取消只针对 Ctrl+C；命令真正执行失败时仍停止后续步骤并显示错误。不把失败写成卸载完成，不尝试恢复已经删除的实例磁盘。查看状态查询过程中 Ctrl+C 停止只读查询并返回主菜单，不需要回退；查询完成进入结果页后 Ctrl+C 直接退出脚本。一个任务完成后的确认页、结果页重新按静态页面处理。

操作失败先停止后续步骤，结果页显示失败动作、原因、实际变更或未确认结果和日志位置，等待一次回车再返回。提供执行前摘要、参数校验与会话内保留、阶段进度和真实服务状态验证。失败页支持查看诊断日志，并仅在适合安全重试时重新预检后执行；全部卸载、Incus 清除及回退未完成不提供直接重试。非交互失败退出非零且不等待输入。可软中断的命令行操作完成必要回退后以中断状态退出。日志不保存初始管理员密码。对应本次 A13，PTY 与 mock 只证明脚本流程，不代替实机安装生命周期。

用户提示使用具体动作和结果，正常完成只报告一次。成功、软中断处理中、回退完成、回退失败和结果未确认分别表述；只检查服务 active 时显示“运行中”或“已启动”，只修改网桥 IPv6 配置时说明已配置、不宣称公网已连通。删除提示说明具体数据范围，失败提示保留可用的原因和日志位置。终端文案以用户提交的部署脚本草案为准。

安装入口是 GitHub Release 上的 `install.sh`。打版本 tag 后，GitHub Actions 构建 linux amd64 Agent，并上传二进制、`install.sh` 和 SHA256。脚本只从 Release 下载；校验失败或没有可用资产时失败，不改已有程序、配置和 Incus 资源。对应本次 A13。

首次安装在 Debian 13 amd64 上以 root 执行，安装 Incus 依赖并准备 `particeps` 项目、`particepsbr0` 和 LVM thin 的 `particeps-pool`。新池默认建议为根分区可用整 GiB 的 30% 向下取整，最少 1 GiB、最多 25 GiB、不超过实际可用量；不足 1 GiB 拒绝。交互允许输入 1 至可用 GiB 的整数，回车使用建议值，大小在最终安装确认页展示，不再单独重复一次 Y/n；非交互用建议值。已有 lvm 池及项目保留，池为其他驱动时拒绝，不改既有池大小。安装状态不完整时说明缺少什么，不擅自当成全新安装覆盖。

网桥 IPv4 固定为 `10.80.0.1/24`、NAT 开启。母机非回环、非容器/虚拟网桥接口存在 scope global IPv6（含 ULA）时，新桥启用 `ipv6.address=auto` 和 `ipv6.nat=true`；没有时新桥禁用 IPv6。既有桥的 IPv4 地址/NAT 不符合预期则拒绝；仅在检测到母机 IPv6 且原桥 IPv6 为空/none 时补配，其余既有 IPv6 配置保留。地址检测不证明公网 IPv6 出口，也不代表 Agent 已实现 IPv6 实例管理。

已有 `/etc/particeps/config.yaml` 不覆盖。新配置默认监听 `0.0.0.0:8792`，HTTP Cookie 非 Secure；HTTPS 部署显式设为 Secure。程序、配置和数据仍使用 `/opt/particeps`、`/etc/particeps`、`/var/lib/particeps`。首装无管理员时生成 20 位字母数字密码，经 `--bootstrap-only` 保存哈希，安装终端展示面板 IPv4 地址与密码，不写 `admin-bootstrap.txt`；已有管理员不重置、不重复交付。管理员密码不进入普通日志或 API。

升级只替换 Agent 程序：先备份程序、systemd 单元、配置和管理库（SQLite 在线备份含 WAL，存在的 metrics.db 也备份，目录 `0700`），不含小鸡磁盘；不改实例、网桥、存储池和配置值。原已停止的服务保持停止；重启失败退出非零并给出备份位置。`--status` 显示 Agent/Incus 状态、监听地址和最近备份。`--rollback` 从最近一次升级备份恢复上述四类文件。无参数且在终端时提供五项菜单：安装/升级、状态、回滚、全部卸载、只卸 Agent。

全卸执行前必须输入 `PURGE`，删除 Agent、配置、数据、particeps 项目内全部实例、`particepsbr0`、`particeps-pool` 和项目。此步骤保留其他项目及 Incus；随后列出其他项目实例并说明数据清除影响，再单独询问是否卸载 Incus。默认否，非交互保留；明确输入 y/Y 后才 apt purge Incus/lxcfs 并清除 Incus 数据目录，此选择会清除其他项目实例。`--keep-instances` 只停止并移除程序与服务，保留配置和管理数据，不进入 Incus 清除流程。并发安装/升级使用锁，第二路被拒绝。

本切片不提供平台 Token、完整 IPv6 安装向导、本地二进制旁路或自动升级服务。自动网桥 IPv6 准备不代替后续网络交付。原 A56 仍由 S7 主归属；8–16 台集成和完整剩余空间预算不因 A13 完成。

[完整首期基线](../../../../../planning/first-release/brief.md)保留原产品目标、用户来源、D1–D34、原 A1–A81 与非目标。[交付计划](../../../../../planning/delivery-plan.md)为每个原 ID 保存唯一主归属及当前门槛的部分覆盖关系。未被后续明确决定覆盖的承诺保留；冲突的端口旧语义按 brief 的 superseded 关系执行。当前编号为本 change 的局部编号。

资源压力、完整任务/重装、完整 SSH 策略矩阵/凭据恢复/终端、指定出口与 IPv6 网络、完整监控和 8–16 台集成由后续独立交付完成。当前创建所需 SSH 和 Windows 登录路径属于本轮必要修复，其通过不代表完整 S3 通过。未完成的功能不能宣称可用或返回虚假完成。当前采用顺序普通 Native change，不增加 Supervisor/Child。

## 验证与后续边界

实验基线沿用 Win11 VMware Workstation 中的 Debian 13 x86_64、2 vCPU、4GB RAM、50GB 虚拟磁盘。每次验证记录实际配置、Incus 版本、源代码/二进制、客户端和实例位置、检查结果与清理情况。实际环境准备属于前置条件，不因现有历史记录而假定当前仍完全一致。对应本次 A12。

当前至少两实例的共享入口实验不代替原 8 台与 16 台管理/监控目标。私网 IPv4 和 ULA IPv6 不证明真实公网；TCP 22 探针不证明 SSH 登录；静态限额不证明压力结果。

本轮从 Windows 经已分配入口实际认证到目标实例并执行命令，分别核验已报告的 SSH 故障修复和新创建 Alpine、Debian 的登录路径。默认未启用端口不应出现实际映射，可选 UDP 经显式启用后以真实流量验证；按需启用/禁用和新建行为不得破坏旧实例已有服务。测试前重新读取当前实例与分配，只清理本次可核对归属的测试资源，不依赖较早的空环境或实例名单。

实际停止/重启 Agent 时核对实例、IPv4 转发、外部既有连接与管理数据。管理进程停止不应拆除数据通路。对应本次 A11。

基础交付完成需要本次 A1–A13、对应完整规格和必要检查全部满足，并经 Runtime 接受独立验收。A13 优先。原完整首期由最后集成交付全量复核原 81 项，不因本次归档而自动完成。
