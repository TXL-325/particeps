# 验收示例

以下为本次交付的局部 A1–A12。全部场景须有当前候选的真实结论；原编号与本次编号的映射见交付计划。

- A1：Linux amd64 Agent 在已准备的 Debian 13 实验母机启动，以同一二进制提供嵌入式 Web 和 /api/v1；管理 ID、Incus 实例与查询对象对应。创建、查询、启停和删除仅操作本项目受管资源，其他工具的实例与参考仓库保持原样。
- A2：对本次创建、查询、端口修改、启停和删除接口，未认证请求被拒绝；只读 Token 只能查询，管理 Token 可按权限执行，撤销后立即失效。会话写入执行来源校验，不能绕过管理权限。
- A3：管理员密码、API Token 和小鸡初始密码不进入普通查询或日志。自动生成的初始凭据加密暂存，只能由管理权限领取一次；领取后清除，过期后不可领取并清理暂存内容；错误、重试和迟到响应不重新暴露凭据。
- A4：默认系统为 Alpine，Web/API 同时提供 Alpine 和 Debian 13。一次正常请求可创建至少两台分别识别的 Incus 系统容器，逐台结果可查询且与实际状态一致；另核对两种系统的实际运行系统、镜像来源和管理身份，不能用任务受理或 running 单独代替创建结果。
- A5：默认端口池为 20000–59999，每台初始分配 20 个连续号码，池与数量可配置；同一号码的 TCP/UDP 归同一实例。号段首个 TCP 转到该实例 22，其余 TCP 和全部 UDP 默认同号，实际目标可核对且不额外占用 SSH 号码。
- A6：至少两台实例共享一个已核对属于母机的 IPv4 入口，外部客户端 TCP/UDP 到达各自正确目标。自动分配跳过已占用号码，手工指定冲突被拒绝；并发请求不得重叠分配，宿主服务和非本系统 forward 对象不被接管、覆盖或清理。
- A7：已有实例可自动追加或指定可用号码，也可按协议编辑目标端口；实际转发、重新查询和界面展示一致。号码归属不变，修改一台不改变另一台规则或中断其已建立的连接。
- A8：对单台实例停止和启动时保留已分配号码、单端口和自定义目标；停止后暂停其 DNAT，另一台保持可达。启动后按观察到的内部 IPv4 重绑；地址丢失或操作结果未确认时显示等待/待核对且不复用旧归属，恢复后原 UDP 客户端可继续通信。
- A9：删除时先摘除本实例映射并精确清理相关连接，确认实例删除后才回收号码。清理失败、写入中断或结果不明时保留占用和可查询原因，阻止危险重试/重分配；成功删除一台不影响另一台规则和连接，回收号码不得把旧入口连接导向新实例。
- A10：本次创建、端口查询/追加/编辑、启停和删除均可通过 Web 与 API 完成，遵循一致的校验、权限和结果语义，并有对应接口说明。失败或待核对状态清楚；修改后未取得新查询时不沿用旧的已应用或 SSH 标记，切换实例后的迟到结果不能覆盖当前对象。
- A11：实际停止并重新启动 Agent，核对已运行实例、IPv4 转发与外部既有连接在管理进程停止期间继续工作，管理数据保留且恢复后可查询。记录连续性结果；暂停进程或仅观察服务重启后的 running 状态不能代替该场景。
- A12：记录候选源码/二进制版本、实验母机配置、客户端和实例位置、检查前后结果及测试资源清理。交付保留完整首期基线及原 A1–A81 的唯一主归属和依赖映射。相关开发检查和独立复核完成，并实际操作浏览器覆盖本次流程；未完成或不在本次范围的能力明确标识，不能把 HTTP 200、字段存在、端口 22 探针或历史测试扩展为完整功能成功。

# 约束与不变量

- Web 与 API 共用业务规则和授权；只操作可核对归属的本系统资源。
- 正常业务流量通过 Incus/内核规则，Agent 不做逐包代理；停止 Agent 不应停止小鸡或拆除现存转发。
- 同一入口共享 forward 的修改保留其他实例规则；固定 Incus 6.0.4 不把 If-Match 当作已验证的并发保障。
- 状态先记录、后端终态与回读后再报告成功；结果不明保留占用并禁止盲目重试。不能删除 raw.lxc/cgroup 限制以绕过启动失败。
- 临时凭据不可长期明文查询；过期和领取均有清除行为，错误与迟到响应不恢复已清除内容。
- 本地私网/ULA、静态配置、探针和历史测试各自只证明相应范围；不能代替真实公网、SSH 身份、负载或规模证据。
- 原首期 81 项持续有效；部分覆盖不等于原验收通过，最终首期还需全量集成。
- 当前完整 Spec 只描述本次交付；完整首期方案不作为本次归档后的已实现能力发布。
