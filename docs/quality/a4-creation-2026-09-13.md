## 修复与复核

在 `http://192.168.143.145:8792` 实际复现错误：`isSecureContext=false`、`crypto.randomUUID=undefined`、`crypto.getRandomValues` 可用。旧页面在发送创建请求前失败，数据库没有因此生成任务。

- [请求标识工具](../../web/src/utils/requestKey.ts)优先使用原生 UUID；缺失时使用安全随机数生成 UUID v4，支持安装脚本默认的 HTTP 访问方式。
- [创建逻辑](../../web/src/composables/useBatchCreate.ts)统一忙碌态、错误处理和请求标识。提交中防止重复事件；当前页面内每份未确认请求保留自己的 key，确认成功仅清除对应项，离开页面时清空。
- 表单提交期间禁用编辑、提交和取消。路由失败保留可重试状态；页面离开后的迟到结果不覆盖当前界面。

Builder 为 `/root/a4_create_builder`，独立 Reviewer 为 `/root/a4_create_review`。初审发现“A 已受理但丢失响应 → 修改参数的 B 被拒绝 → 恢复 A”会丢失旧 key；修复并新增行为回归后，复核结论为 passed。

## 实机与浏览器结果

母机为 Debian 13.6 / Linux 6.12.107 / Incus 6.0.4，约 4 GiB 内存、2 vCPU；父 CPU 上限为 1.5 核。存储使用 12 GiB LVM thin 的 `particeps-pool`，网桥为 `particepsbr0`（10.80.0.1/24 NAT）。实验入口为母机 VMnet2 的 `10.90.0.10`，Windows 客户端为 `10.90.0.1`。

开始时地址池为空，后端会拒绝 IPv4 创建；通过现有设置页面勾选 `10.90.0.10` 并设置同一 NAT IPv4 后开始验证。期间发现非测试实例 `guest`、`guest1` 已使用该入口，因此保留此设置及两台实例，后续操作移至独立测试标签页。

| 测试实例 | 创建方式与模板 | 核对结果 |
| --- | --- | --- |
| `a4-alpine-20260913-1` | 面板批量 2 台；默认 Alpine、0.5 核 / 128 MiB / 1 GiB | 实际 Alpine 3.21.7；任务 ok/done，Incus Running，API networkStatus=ready |
| `a4-alpine-20260913-2` | 同一批次 | 实际 Alpine 3.21.7；任务 ok/done，Incus Running，API networkStatus=ready |
| `a4-debian-20260913` | 面板选择 Debian 13；自动调整为 0.5 核 / 256 MiB / 4 GiB | 实际 Debian 13.7（trixie）；任务 ok/done，Incus Running，API networkStatus=ready |

两种系统均从实际 Incus 对象读取镜像信息、`volatile.base_image` 和 `user.particeps.id`，并在容器内读取 `/etc/os-release`，与任务和管理 ID 对应。Debian 的 cloud-init 已完成且无错误，初始化后 root 密码处于已设置、未锁定状态；这不等同于 SSH 登录验证。

Alpine 批次实际双击提交，数据库只有一个对应任务、两个子项。通过 API 用两种原请求及原 key 再次提交，均 HTTP 202 返回原任务，测试任务总数保持 2、子项保持 3。

实际操作任务页领取各实例凭据并进入详情。Alpine 返回两份、Debian 返回一份 16 位密码；再次领取均为空，数据库三项 `result_json` 长度均为 0。清除显示和进入详情后不再显示凭据。普通任务查询仅返回可领取标记，报告未保存密码或会话凭据。
