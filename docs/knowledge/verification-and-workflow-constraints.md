# 按任务风险控制验证范围与流程成本

类别：强制约束（Comet 类型：`constraint`）。

适用范围：本项目内 Comet 任务的调查、开发、验证、修复和交付。

来源：用户于 2026-09-12 审阅规则并明确授权写入。

1. **按改动选择验证。** 文案、样式调整以内容检查和浏览器查看为主；普通逻辑修改运行相关测试；认证、权限、数据一致性、并发等改动补充必要的回归验证。不得默认对所有任务执行全套检查。

2. **禁止机械重复测试和构建。** 不得把 `npm test`、`npm run build`、全仓测试或 race 检查作为每次编辑后的固定步骤。构建和较广范围的回归应集中在候选完成时，按交付需要执行。检查通过后，只有相关代码、依赖、配置、环境变化或出现新的具体风险，才允许重跑。

3. **新增测试必须有明确价值。** 测试应覆盖业务行为、重要边界或实际回归风险。低风险、易撤销的修改不默认新增测试；避免重复覆盖和紧贴实现细节的断言。不以测试数量衡量质量，也不为减少数量删除有效测试。

4. **前端验证优先使用现有浏览器能力。** 优先复用 Chrome 控制、开发服务和热更新。不得因某一种浏览器集成不可用就断言无法控制浏览器；已有能力足够时，不得另搭自动化设施。组件、SSR 或 mock 测试通过，不得表述为真实浏览器验证通过。

5. **Docker 必须服务于明确的验证需求。** 只有需要 Linux 行为、系统依赖或环境隔离时才使用，并简短说明具体测试对象。不得将 Docker 作为普通前端检查的默认步骤；使用时必须复用可用的镜像、依赖和编译缓存，避免重复下载与编译。

6. **Comet 必须复用已有进度和证据。** 当前流程中的续作复用已确认范围、完成状态和有效检查结果，不因用户说“继续”而重新初始化或重复确认。独立复核在候选就绪后开展；修复轮次只重查失败或受影响部分。最终验收仍核对全部既定验收项，但不得因此机械重跑所有命令。

7. **流程不得扩大任务范围。** 不得把与当前目标无直接必要关系的组件重构、测试设施建设、文档扩写等捆绑进普通修复。必要扩展应及时说明原因和影响；范围明确、已经授权的工作持续完成，不额外增设确认环节。

8. **满足交付条件后及时结束。** 相关检查通过且没有未解决的具体风险时，应交付结果。追加耗时检查前必须说明它要解决什么尚未验证的问题；交付时简要列出改动、实际验证和未覆盖范围，不以重复检查延长任务。
