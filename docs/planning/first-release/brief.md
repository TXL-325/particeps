据此采用方案 1：允许单台额度之和超过总上限（超分），但所有受管小鸡的**实际** CPU 时间合计不得超过管理员设定的合计硬上限。该上限用 cgroup v2 父组 `cpu.max`（CFS 带宽）执行，不是 Incus 项目 `limits.cpu` 记账。出厂默认为母机逻辑 CPU 数的 75%，可在 Web 修改。单台 0.5 核等额度仍是该台硬上限。总上限不限制 Agent、Incus 与母机系统进程。

2026-09-11，CPU 额度与管理员终端澄清：

> 0.5 核这种形式在后续扩展到PODMAN时，是否可用？A38：创建小鸡时可导入 SSH 公钥……我们作为管理者，在使用这种形式时是否无权进入终端？

据此：“N 核”是 CPU 时间硬上限（每 100ms 可跑 N×100ms），不是 vCPU 个数。首期映射到 Incus `limits.cpu.allowance`（0.5 核 = `50ms/100ms`）。同一口径可映射到后续 Podman 的 cgroup CFS 配额（0.5 核 = quota 50000 / period 100000）。首期仍不交付 Podman 后端。A38 只验收持有对应私钥的 SSH 登录；管理员进入小鸡走独立的 Web 终端（Incus 执行通道），不依赖导入的公钥、私钥或 SSH 端口。仅导入他人公钥、关闭密码登录或 SSH 不可用时，有管理权限的管理员仍可打开 Web 终端。

## 已确认的产品范围

本项目专注于母机 Agent。Agent 内置管理本母机的 Web 面板与 API。管理员可在浏览器中批量管理小鸡、查看监控；外部程序通过版本化 API 调用。协议、认证、任务恢复与监控保留均已列入本次完整方案。

首期小鸡采用 Incus 系统容器，运行完整 Linux 用户空间并共享母机内核。日常监控以资源用量为主，不提供母机进程列表。选定小鸡详情可查看该小鸡内部进程。Podman 或独立内核虚拟机后端尚未纳入首期确认范围。

首期管理由 particeps 新建的小鸡，已有 Incus 或 runman-agent 实例的接管与管理数据迁移另行设计。

母机公网资源由 Agent 自动检测，管理员在 Web 勾选小鸡可用的 IPv4/IPv6 地址与前缀。按池内能力提供 IPv4 SNAT 与 DNAT/端口映射、独立公网 IPv4、IPv6 NAT66、以及前缀直路由/独立公网 IPv6。支持 IPv4-only、IPv6-only 与双栈；有可用 IPv6 前缀时优先独立公网 IPv6。

初始系统镜像包含 Alpine 和 Debian 13，默认选择 Alpine，创建时可以切换到 Debian 13。

小鸡支持 SSH 公钥和每台独立设置或生成的初始密码，可关闭密码登录。实例详情提供通过 Incus 进入运行中小鸡的 Web 终端；该通道不依赖导入的公钥或对应私钥。

本地验证基线为 Win11 VMware Workstation 中的 Debian 13 x86_64 虚拟机，2 vCPU / 4GB RAM / 50GB 虚拟磁盘，由用户准备 IPv4、IPv6 和 NAT 模拟网络。每台母机的目标数量为 8–16 台小鸡；原「816 台」已由用户明确纠正。

## Incus 实现依据（设计参考）

2026-09-10 查阅官方 main 文档和当前 API 源码，得到以下依据；它们不是新增用户承诺，也不代表已在目标母机验证：

- [`limits.cpu` 与 `limits.cpu.allowance`](https://linuxcontainers.org/incus/docs/main/reference/instance_options/#cpu-limits) 分别控制可使用的 CPU 和 CPU 时间。容器支持运行中修改。`50%` 属于争用时的软限制，`50ms/100ms` 才是相当于 0.5 个逻辑 CPU 的时间硬上限；`200ms/100ms` 对应最多两个逻辑 CPU 的时间。默认同时加硬上限和绑定会限制调度空间，因此绑定应作为有明确需求时的选项讨论。
- [Incus network forwards](https://linuxcontainers.org/incus/docs/main/howto/network_forwards/) 可以按 TCP/UDP 单端口或端口集合转发到不同实例，支持连续端口范围和目标端口映射。端口分配账本、范围冲突、SSH 规则及回收仍需由 particeps 定义。
- [Incus proxy 的 NAT 模式](https://linuxcontainers.org/incus/docs/main/reference/devices_proxy/#nat-mode) 也支持 TCP/UDP 转发，要求母机作为实例网关；其特征是保留客户端地址。具体转发方案将按目标网络与 Incus 版本确定，不把 Agent 自身当作默认流量代理。
- [实例状态 API 结构](https://github.com/lxc/incus/blob/main/shared/api/instance_state.go) 包含累计 CPU 纳秒、网卡计数、运行时 PID 和进程总数。进程总数不能代替进程列表；小鸡内部进程需要额外采集并与实例身份对应。
- CPU 与网卡累计计数可通过相邻采样计算使用率和速率；新的 `allocated_time` 等字段带 API extension 条件，不能假设所有部署版本可用。目标版本和能力检测在实现方案中明确。

## 原首期工程默认值

以下工程默认值随原首期方案提出，不伪称为用户逐项原话；本文件保留它们供后续交付逐项兑现：

- Go Agent + Vue 3/TypeScript 静态前端：构建后的网页文件打进 Agent 程序，由 Agent 自己提供管理页面，母机上不需要再运行 Node 服务；systemd 运行；管理与指标各用一个 SQLite 文件。
- Debian 13 官方 Incus 6.0 系列容器包；专用项目、LVM thin pool 和 ext4。池上限初始 32 GiB，并在池外至少预留 8 GiB 可用空间，实际安装按空间检查调整。
- 可编辑模板：Alpine 0.5 核 / 128 MiB / 1 GiB，Debian 13 0.5 核 / 256 MiB / 4 GiB；带宽默认不限制。额度与实际占用分开表达。
- 常用系统做成已记录指纹的就绪镜像，后续创建复用，避免每台重复做相同初始化；镜像更新只影响显式新建或重装。
- 初始化同时使用发行配置与实例启动后的核对/补齐，不把 cloud-init 成功当成唯一就绪条件。
- 保存期望电源状态，并设置 Incus 对应的开机自启，避免把“曾经创建时为 running”误当成当前应运行。
- 单管理员会话 + 可撤销的只读/管理 API Token；/api/v1 JSON API 与 OpenAPI 文档。默认监听 127.0.0.1:8792，可通过 SSH 隧道或显式测试网卡配置访问；公开部署使用 HTTPS。
- 初始密码只在受保护的初始化交付提供，临时执行凭据加密并及时清除，普通查询和日志不回显。重装默认保留公钥，密码按本次请求设置或重新生成。
- 任务采用幂等键与明确的逐实例状态；细节结果默认保留 30 天，未完成和待核对任务不自动清理，精简幂等标记保留以避免重复动作。
- CPU 显示已用核数和当时额度比例；缺测明确标识，历史不被后续改配重算。分钟汇总保留均值、峰值和有效样本信息。
- 首期手动安装/更新，更新前备份管理配置与数据库，保持实例和网络；备份清单不包含小鸡系统盘。Agent 移除默认保留数据与实例。

- A69：可为全部小鸡设置默认的唯一来源 IP 上限，也可按小鸡覆盖；0 表示不限制。达到上限后，新的来源 IP 被拒绝，已在限额内的来源仍可建立连接。面板能查看当前活跃来源数与生效限额。
- A70：Agent 能检测母机上行接口上的全局 IPv4、全局 IPv6 地址以及可识别的 IPv6 前缀，并在 Web 中展示检测结果与来源接口。
- A71：管理员可在 Web 勾选小鸡允许使用的 IPv4 地址、IPv6 地址和 IPv6 前缀；未勾选的地址不用于新的分配或映射。
- A72：池中有 IPv4 时，小鸡 IPv4 出站使用 SNAT，源地址为管理员指定的 NAT IPv4。
- A73：池中有 IPv4 时，端口映射监听在管理员指定的公网 IPv4 上，DNAT 到对应小鸡。
- A74：池中有可分配的额外公网 IPv4 时，可为小鸡分配独立公网 IPv4；该地址不再用于其他小鸡的独占分配。
- A75：池中有 IPv6 地址但没有可用前缀、或管理员选择 NAT66 时，小鸡 IPv6 出站 SNAT、入站可在该 IPv6 上做 DNAT/端口映射。
- A76：池中有 IPv6 前缀时，默认优先为小鸡分配独立公网 IPv6，而不是 NAT66。
- A77：池中仅有 IPv4、或创建时选择 IPv4-only 时，小鸡只有 IPv4 连通性。
- A78：池中仅有 IPv6、或创建时选择 IPv6-only 时，小鸡只有 IPv6 连通性；同族 IPv6 入站可用，不把 IPv4 映射到 IPv6-only 小鸡。
- A79：池中同时有 IPv4 与 IPv6 能力且选择双栈时，小鸡同时具备已启用的 IPv4 与 IPv6 连通性。
- A80：Web 创建设置只列出当前池能支持的网络模式；不支持的组合被拒绝并说明缺少哪类地址或前缀。
- A81：管理员可设置所有受管小鸡的合计 CPU 时间硬上限。无论实例数量以及单台额度之和是否超过该上限，这些小鸡的实际 CPU 时间合计不超过该上限。出厂默认为母机逻辑 CPU 数的 75%，可在 Web 调整。单台额度仍为该台硬上限。单台额度大于合计硬上限的配置被拒绝。该上限不限制 Agent、Incus 守护进程和母机系统进程。

# 约束与不变量

- 用户明确指定 particeps 为独立项目。
- 本项目专注于母机 Agent。
- Agent 内置 Web 面板与 API，面板管理本母机，API 供外部程序调用。
- 首期采用 Incus 系统容器；日常监控为资源用量，不提供母机进程列表；小鸡内部进程仅作为详情诊断。
- 批量操作覆盖创建、启动/停止（含强制停止）、重启、CPU/内存/磁盘/带宽调整、重装、删除和密码重置，逐台展示进度与结果。
- 保存期望电源状态；转发由 Incus 管理，Agent 重启不中断已生效转发。
- 可限制每台小鸡同时接入的唯一来源 IP 数；全局限额可被单台覆盖，0 表示不限制。
- 端口分配同时支持批量创建时的连续号段和后续单端口追加、指定。
- 默认端口池 20000–59999、每台 20 个号码可调整，TCP/UDP 同归属；首个 TCP 映射到 22，其余默认同号转发，目标可编辑，清理完成后才回收。
- CPU 分配采用共享算力时间硬上限（“N 核”不是 vCPU 个数）与可选逻辑 CPU 绑定，默认由系统调度。该口径可映射到后续 Podman CFS 配额；首期仍只实现 Incus。
- 所有受管小鸡另有合计 CPU 时间硬上限（cgroup 父组配额）；允许单台额度超分，实际合计不得超过该上限。默认母机逻辑 CPU 的 75%，可调。
- 管理员进入小鸡使用 Web 终端（Incus 执行通道），不依赖 A38 导入的 SSH 公钥或对应私钥。
- 实例网络按母机已勾选的 IPv4/IPv6 资源组合；有 IPv6 前缀时优先独立公网 IPv6。
- 管理员在 Web 控制小鸡可使用哪些 IPv4/IPv6 地址与前缀。
- 首期系统镜像提供 Alpine 和 Debian 13，默认 Alpine。
- 小鸡 SSH 支持公钥、独立设置或生成的密码，以及禁用密码登录；实例详情包含 Web 终端。
- 监控包含母机概览、母机和小鸡的 CPU、网络实时图表与历史曲线；实例列表显示实时资源；选定小鸡详情可查看内部进程的实时 CPU、内存与排序。
- 可登记本机已导入的 Incus 镜像作为额外系统选项。
- 首期仅管理 particeps 新建的小鸡，已有实例接管与迁移另行设计。
- 验证环境为 Win11 VMware Workstation 上的 Debian 13 x86_64、2 vCPU / 4GB RAM / 50GB 虚拟磁盘；本地网络模拟与真实互联网验证分别记录。
- 每台母机的本地数量目标为 8–16 台小鸡；已根据用户澄清替换原「816 台」。
- 用户要求深入讨论功能和实现方案；当前不将初始请求当作完整方案确认。
- 「参考项目已有」不等于「particeps 已承诺」；用户决定后立即同步本 brief 与目标规格。
